# 快照与恢复

CatOS 使用 Btrfs 提供快照能力，并由 Snapper 管理快照的创建、描述和保留。启动工具负责让合适的快照能够进入启动菜单，但不会替代 Snapper 管理快照本身。

## 职责边界

```text
软件事务或人工操作
        ↓
Snapper 创建和管理 Btrfs 快照
        ↓
启动集成捕获所需的内核与 initramfs 资源
        ↓
Limine 菜单提供可启动的快照入口
```

启动集成不应该：

- 创建或删除 Snapper 快照；
- 修改默认 Btrfs 子卷；
- 把只读快照直接改成可写；
- 在没有明确操作的情况下自动执行系统回滚。

## 为什么只存在快照还不够

`/boot` 中的内核和 initramfs 往往不位于根子卷快照中。若更新后只保留根文件系统快照，却没有与其匹配的启动资源，菜单中的快照可能无法真实还原更新前状态。

因此 CatOS 的目标是让快照元数据、根文件系统和启动资源具有明确关联，而不是简单扫描目录后生成菜单项。

## 查看快照

```bash
snapper list
```

快照描述应说明创建原因，例如软件事务前后、人工创建或计划任务。恢复前确认目标快照时间和对应的软件变更。

## 回滚不是备份

快照通常和原文件系统位于同一块磁盘，不能抵御磁盘损坏、丢失或整盘误操作。重要数据仍然需要独立备份。
