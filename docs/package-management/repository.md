# CatOS 软件仓库

CatOS 仓库用于交付发行版自身需要维护的集成包，例如安装器配置、桌面预设、主题、启动工具和系统策略。通用软件仍应优先来自 Arch Linux 官方仓库。

## 软件来源

一个典型的 CatOS 系统可能同时使用：

1. Arch Linux 官方仓库；
2. CatOS 正式仓库；
3. 用户明确启用的其他仓库或 AUR 构建结果。

来源越多，软件包覆盖和文件冲突的可能性越高。加入第三方仓库前应确认优先级和签名策略。

## 构建身份

已经发布到正式仓库的包不应在同一个源码提交上重新构建并覆盖。需要重建时，应先更新对应的 source commit，使新的产物拥有新的构建身份和可追溯来源。

## 更新系统

使用完整系统更新：

```bash
sudo pacman -Syu
```

不要长期进行部分更新。若仓库同步暂时不一致，应等待仓库恢复，而不是绕过依赖约束强行安装。

## 诊断包来源

```bash
pacman -Qi package-name
pacman -Si package-name
```

检查已安装版本、打包者、构建时间和仓库来源，有助于区分上游问题、CatOS 集成问题和本地覆盖。
